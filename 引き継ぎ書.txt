2. 在庫管理表の仕様
========================================

【スプレッドシート構成】
- 売上管理: 全プラットフォームの売上を自動記録（A〜O列）
- 在庫サマリー: 商品ごとの仕入単価・在庫数・利益管理
- 商品マッピング: キーワード→商品名（A=キーワード、B=商品名、C=個数、O=送料）
- 仕入リサーチ: 仕入れ情報
- 月次集計: 月ごとの集計

【売上管理シート列構成】
A=日付、B=商品名、C=プラットフォーム、D=出荷数、E=販売単価、F=売上、
G=仕入単価、H=仕入価格、I=送料、J=販売手数料、K=利益、L=利益率、
M=商品ID、N=ステータス、O=備考

【GASの仕組み】
- GASがGmailを5分おきに自動監視し、注文メールを売上管理シートに自動記録
- メインファイル: コード.gs（GASエディタ上）
- バックアップ: /home/user/sedori-kanri/在庫管理表.rtf

【主要関数】
- checkSalesEmails: メイン実行関数（5分トリガー）
- processMercariEmails / processSingleMercariMessage: メルカリ処理
- processYahooAuctionEmails / processYahooAuctionBatch: ヤフオク処理
- processYahooFleaMarketEmails: ヤフーフリマ処理
- processMercariShopsEmails: メルカリShops処理
- processRakumaEmails: ラクマ処理
- processYahooPaymentConfirmedEmails: Yahoo確定メール処理
- mapProductName(rawName): キーワードで商品名マッピング
- mapProductQty(rawName): 商品マッピングから個数取得
- recordSaleAuto(...): 売上自動記録
- isAlreadyProcessed / markAsProcessed: 処理済みフラグ管理
- exportSalesCSV(): CSV出力（確定申告用）

3. これまでの修正履歴（全て完了済み）
========================================

【①ヤフオク価格が¥0になる問題】
- 原因1: 正規表現が落札金額[：:]だったがメールは全角スペース区切り
  → 修正: /落札金額[\s：:　]*([\d,]+)\s*円/
- 原因2: 「支払い完了」メール処理時、ステータスのみ更新して価格を更新していなかった
  → if (existingRow > 0) ブロックに価格・売上・手数料・利益の更新処理を追加

【②セット商品の売上が2倍になる問題】
- 対象: 蓄光テープ 2個セット（¥980）→ 売上が¥1,960になっていた
- 原因: recordSaleAuto で sellPrice: price(980)のまま渡し、qty(2)×price(980)=1,960と計算
- 修正: qty > 1 のとき sellPrice = Math.round(price / qty) に変更
  var qty = mapProductQty(rawName);
  recordSale(sheet, {
    qty: qty,
    sellPrice: (qty > 1) ? Math.round(price / qty) : price
  });
- 結果: 出荷数=2、販売単価=490、売上=¥980 ✓

【③処理済みフラグが誤ってセットされる問題（全プラットフォーム対応済み）】
- 症状: メールが届いているのに売上管理に反映されない
- 原因: isDuplicateRowがtrueを返した場合（行未作成）でもmarkAsProcessedが呼ばれフラグだけ残る
- 修正: 全プラットフォーム関数にactedフラグを追加
  var acted = false;
  if (existingRow > 0) { updateRowStatus(...); acted = true; }
  else {
    if (nameRow > 0) { updateRowStatus(...); acted = true; }
    else if (!isDuplicateRow(...)) { recordSaleAuto(...); acted = true; }
  }
  if (acted) markAsProcessed(msg.getId());
- 対応済み: ヤフオク、ヤフーフリマ、メルカリShops、ラクマ、メルカリ（全て完了）

【④CSV出力機能（完成済み）】
- exportSalesCSV()関数で実装
- メニュー「在庫管理」→「CSV出力」から実行
- 月ごと or 年ごと、プラットフォーム別 or まとめて1ファイルを選択可能
- 保存先: Googleドライブのマイドライブ

4. 重要な注意事項
========================================

【テスト時の手順（必ずこの順番で）】
1. 売上管理シートの対象行を削除
2. スプレッドシートメニューから「処理済みフラグをリセット」を実行
3. トリガーを一時削除
4. checkSalesEmails を手動実行
5. ログ確認
6. テスト完了後、トリガーを再設定（5分おき）

【キーワードの文字コード問題（最重要）】
- ㎜（特殊文字）と mm（ASCII）は見た目が同じでも別の文字
- 商品マッピングのキーワード（A列）は必ずGmailのメール本文からコピペすること
- 全角スペースと半角スペースも別文字なので注意

【LockService競合】
- トリガー実行中に手動実行すると「別の実行が進行中のためスキップ」になる
- テスト時はトリガーを必ず一時削除すること
